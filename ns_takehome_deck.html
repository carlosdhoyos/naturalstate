Part 1

Birds

Turn BirdNET's confidence scores into observations that are at least 99% likely to be correct, following Wood & Kahl (2024), and specify how the platform runs it automatically.

1
Data

Predictions and validation data

29,491 predictions from 43 recorders over 23 days. The ornithologist validated 551 clips (1.9%). The position of a 99% threshold is estimated mainly from the incorrect clips.

The Oriole has 18,054 predictions and no validated errors; the Plover has one. This limits what can be estimated for both species.

1 · Duplicate validations (D-01)

Four Plover clip pairs at RBS75 point to the same 3-second segment, so one clip of each pair is dropped: 551 → 547 distinct clips. A fifth pair is ambiguous and kept; the sensitivity analysis shows it changes nothing.

2 · Linking clips to predictions (D-02)

The two exports name audio differently: predictions round the file start down to the hour and count begin_time_s from it; validation names keep the true start second. Clips are linked on species + recorder + date + hour + score (±0.0005): 476 link uniquely, 69 tie with a same-score prediction, 2 are not found. A human verdict replaces a label only where the link is unique.

3 · Clustering

The 551 clips come from 353 audio files and 32 recorders; 93% of Plover clips come from one recorder (RBS75). Uncertainty is therefore estimated by resampling whole recorders.

4 · Recorder clocks (D-03)

Bird activity (Oriole dawn onset, Nightjar dusk onset vs computed sunrise/sunset) suggests RBS40 and RBS71 run ~3 h behind: UTC rather than EAT. This affects only the time-of-day test, never thresholds.

5 · Validation design (D-12)

Validated clips over-represent high scores: 26% of validated Oriole clips score ≥ 0.9 vs 3% of Oriole predictions, which matches the paper's high-score top-up. Choosing clips by score leaves P(correct | score) unbiased, provided that, within a score, clips were not chosen by their outcome or by factors the model leaves out (such as the recorder); but a raw share-correct over all validated clips would be biased, so none is reported without the model or a score band.

The method · Wood & Kahl 2024

Method: one logistic regression per species

Regress the ornithologist's verdict on the logit of the confidence score, then find the score at which the fitted probability of being correct reaches 0.99.

1 · Score
c
BirdNET confidence, 0.1–1
→
2 · Logit
x = ln(c / (1−c))
linear scale; c clamped to [10⁻⁴, 1−10⁻⁴]
→
3 · Fit
p = σ(β₀ + β₁x)
ordinary maximum likelihood, = R glm(binomial)
→
4 · Solve p = 0.99
t = (ln 99 − β₀) / β₁
threshold = σ(t), rounded up to 6 dp

As in the paper

  • One curve per species, on the logit of the score
  • Ordinary logistic regression, tested against statsmodels to 10⁻⁷
  • "99%" defined per prediction: every model observation has fitted p ≥ 0.99
  • The paper's AIC test of whether the curve transfers across recorders and time

Added for cases the paper does not cover

  • An evidence gate (minimum evidence for an automatic threshold): ≥ 5 correct and ≥ 5 incorrect validated clips
  • Firth regression only as a fallback for separated data
  • No extrapolation beyond the validated score range
  • Recorder review flags that never change a label

Each addition can only reduce the number of automatic observations.

Fitted coefficients (all 150 validated clips: 117 correct, 33 incorrect; ordinary ML)

β₀ = 3.1590   β₁ = 2.0723
t = (ln 99 − 3.1590) / 2.0723 = (4.5951 − 3.1590) / 2.0723 = 0.6930
threshold = 1 / (1 + e−0.6930) = 0.6666381 → stored 0.666639

Recomputed for this deck from the embedded validation file; it matches statsmodels and the pipeline.

Why round up

The exported value is rounded up to 6 decimals and labels use exactly that value, so a Tech implementation of confidence >= species_threshold reproduces the model labels exactly and never admits a prediction below the true 99% point.

Cross-check for Biometrics (R)

v <- subset(read.csv("validation_results.csv"),
  commonName == "Abyssinian Nightjar")
x <- qlogis(pmin(pmax(v$confidence,1e-4),1-1e-4))
m <- glm(v$outcome ~ x, family = binomial)
plogis((qlogis(.99)-coef(m)[1])/coef(m)[2]) # 0.6666381

"99%": per prediction vs per set

The brief uses both "precision ≥ 0.99" and "99% sure that that prediction is correct". The paper and this analysis use the per-prediction reading. The set-level reading (the average of the labelled predictions reaches 0.99, as in Tseng et al. 2025) would give the Nightjar 0.4316 and 4,355 labels. It is computed and offered as a policy choice (B-C5).

Role of the validation errors

The threshold depends on the incorrect clips

All validated clips by confidence score, with correct clips in the upper row and incorrect clips in the lower row. The curve reaches 99% where incorrect clips become rare.

Without errors the curve cannot be estimated, and with one error the result depends on the estimator. A species therefore needs at least 5 correct and 5 incorrect clips before its curve sets a threshold.

Separation

If one score cut divides correct from incorrect clips (or there are no errors at all), the likelihood keeps increasing as β₁ → ∞: ordinary ML has no finite estimate. That is the Oriole (150/150 correct).

Firth regression in this case

Firth's penalised likelihood always returns finite coefficients, but with zero errors its level is set entirely by the penalty. The Oriole's Firth curve is flat (slope −0.06 ± 0.53): the slope is not identified. Reading it at face value would have labelled 17,646 Orioles on the strength of a penalty term.

Why k = 5

It is an evidence policy, not a statistical minimum of logistic regression or of the brief: a pragmatic floor that reduces dependence on extremely sparse outcomes. It is checked by sensitivity analysis at k = 1, 3 and 10:

  • k = 1 admits the Plover at 0.261 (536 labels)
  • k = 3 changes nothing
  • k = 10 also stops the Firefinch, which has no threshold anyway

How the gate came about

A first version made Firth primary for rare-error species and gave the Plover 100 labels on one error. An independent review showed Firth's penalty behaves like an extra error: it pulls fitted probabilities down and pushes the threshold up. The log keeps both versions (D-05 to D-08, then D-09 to D-12).

Review flags (D-11)

For each recorder with ≥ 5 validated clips of a species that passed the gate: refit without that recorder, then ask how surprising its observed number of correct clips is. X is Poisson-binomial with the refit probabilities of that recorder's clips; flag if P(X ≤ observed) < 0.05 / (recorders tested).

  • RBS75: all its validated Nightjar clips wrong vs 4.4 expected, p = 0.0026
  • RBS79: all wrong vs 10.9 expected, p = 2.5 × 10⁻⁸

Their clips all scored ≤ 0.273, so the validation gives no information on high-scoring Nightjar predictions at these recorders. They are therefore flagged and not removed.

Model-free check

All 74 validated clips at or above 0.666639 were judged correct. With 74/74, the Wilson 95% lower bound on the true share is 74 / (74 + 1.96²) = 95.1%. The 99% figure therefore comes from the shape of the logistic curve; the validated clips alone support about 95%. The bound is a binomial reference, not a validation of future performance: it assumes independent, representative clips, while these cluster by recorder and were chosen by score.

Recorder bootstrap (D-12)

Whole recorders resampled 2,000 times; the full procedure, gate included, re-run each time.

  • 93% of resamples produce a threshold; 95% interval 0.471–0.835
  • Labelled count: median 3,123, 95% interval 0 to 4,109
  • Every resample without a threshold leaves out both RBS75 and RBS79

Other estimators

Firth 0.709 and FLIC 0.707, about 200 fewer labels. When both outcomes are plentiful the estimators agree; they diverge only for the rare-error species.

Robust to data handling

Clamp of scores = 1 (10⁻⁴ to 10⁻⁶, or drop): threshold changes in the 8th decimal. De-duplication choices: no decision changes.

The threshold is stable, but most errors come from two recorders

Where the 33 errors come from
RBS75 + RBS79 · 29
4

Two recorders account for 29 of the 33 errors, and all their validated clips scored ≤ 0.273. Without them only 4 errors remain and the Nightjar would not pass the gate, although its threshold would change little (0.686, 3,047 labels).

Recorder or time of day?

26 of those 29 clips are evening recordings. Adding an evening term improves AIC by 14.6, which meets the adoption rule set before the analysis.

The model was not adopted. Without RBS75/79 the evening term cannot be estimated (4 errors, all in the evening; 0 of 68 night clips incorrect), so recorder and time cannot be separated. It is reported as a sensitivity analysis: night 0.4208, evening 0.7272, 3,715 labels.

Next steps

Validate evening and night Nightjar clips at other recorders, and confirm what the RBS75/79 detections are (B-C4). If another species is calling there, the 9 flagged predictions above the threshold should be treated as unconfirmed.

Platform check

A recorder acceptance check: each new recorder receives a small random validation sample per species before its predictions are labelled by the model (suggested: 10 per species across score bands; the recorder passes if the review-flag test does not flag it). Such a check can reveal recorders like RBS75/79; its detection power has not been tested.

Decision: keep the pooled curve, flag the two recorders, and report the evening model as a sensitivity analysis. The departure from the pre-set AIC rule is recorded in D-13.

What was compared

Wood & Kahl suggest adding spatial and temporal covariates and comparing by AIC. All recorders are in one grid, so the spatial unit is the recorder, entered as a random intercept (adaptive Gauss–Hermite quadrature; a fixed recorder term diverges for recorders whose clips are all wrong). Time: evening vs night, and week of season.

Results

  • Score + evening: best of the models that fit, ΔAIC = 14.6 vs pooled
  • Its evening coefficient comes almost entirely from RBS75/79
  • Week term among the other recorders: not supported (+1.7 AIC)
  • Recorder random-intercept models did not converge: inconclusive

Reason for not following the adoption rule

The rule (ΔAIC ≥ 2, identified, computable for any recorder) said adopt. But I cannot tell whether the model describes an evening effect at recorders that were never validated, or just two recorders. This judgement was made after seeing the result and is recorded in D-13.

Partial pooling (Thompson et al. 2025)

A mixed model across species would give the Oriole and Plover a curve, but only by assuming they behave like the other species, which their own data cannot confirm, and which cuts against Wood & Kahl's central point that scores do not transfer between species. With four species, one of them the near-useless Firefinch, the pooled curve would mostly reflect the pooling assumption. It becomes attractive on the platform once many species are validated.

Firth or FLIC for the Plover

ML 0.261 (536 labels), Firth 0.848 (100), FLIC 0.156 (785). A threshold that moves from 0.16 to 0.85 when the estimator changes is not reliable enough to use.

Call density (Navine et al. 2024)

A threshold-free estimate of the share of audio windows containing the species, from validation within score-quantile bins. It needs no errors, so it suits exactly the Oriole. Recommended as a future vocal-activity measure, not as clip labels.

Approach

Approach: flag issues without changing the data

32 survey submissions, 640 quadrats, 1,296 additional-species rows, 31 plot registrations, 51 prescribed points, 11 entity lists and 2 XLSForms. Values are kept as exported, and each issue is recorded as a flag that points to the source row.

One selected survey (canonical) per plot and monitoring round; rejected repeats are kept and used to measure repeatability
The QA run adds flags and summary tables. It does not modify any source value.

Joins

  • Survey → vegplots (via selected_plot_uuid); registration → centroids. vegplots.plot_uuid is the only link between a survey and its registration.
  • Repeat groups are separate tables linked by PARENT_KEY: quadrats → survey, additional species → quadrat.
  • Provisional taxa: species_extra slot → curation key herb_NNN via group_type + unknown_index → species_extra_ids (NS curation, free-text notes).

Traps

  • Multi-selects are space-separated uuids, but some choice names contain spaces ("loam soils").
  • Timestamps are labelled +02:00 although the instants are correct: convert to UTC, derive local days as UTC + 3 h.
  • Lookups keep the first row of a duplicated key, so duplicates reach rule A02 instead of crashing an earlier step.

Resolved taxon (V-02)

Map slot → herb_NNN; follow "duplicate of X" merges to the end; excluded → excluded; curated name → name; curated "Unknown" → its own unresolved taxon. Spellings are never corrected; they are flagged (F03, F13).

Severity

  • error: violates a documented requirement or prevents reliable interpretation
  • warning: plausible, needs review
  • info: context

A rule has a default severity; a single result can be raised or lowered with a stated reason (e.g. a GPS z-score tier). A value the form could not have produced is an error with action "investigate (possible manual edit)".

  • Every quadrat photo inside its survey window; no upload before its form ended

Process risk with no records affected (B06, B10, F09, K03)

Systematic layout (D05, E13)

What each clue does and doesn't show

  • Altitude: Android can report height above the WGS84 ellipsoid rather than sea level, but the two differ by at most ~±100 m anywhere on Earth. A 705 m offset shared with NS's own centroid list points to the coordinates or the dataset, not to the field teams.
  • GBIF: "no record found by this query", not absence. Collection effort, synonymy and record quality all matter; a single missing record is weak evidence, but a fifth of the list is a pattern. Native-range data (POWO/WCVP) would settle it.
  • Mokoro, +02:00, device names: each is weak alone, but all are consistent with the same explanation.

How the pipeline handles it

E14 compares the whole dataset with SRTM once (a project row) and flags a submission only when it departs from that dataset-wide offset by > 100 m, so a dataset offset is never blamed on the field. GBIF and elevation are read from caches refreshed by a separate job, so the QA run stays offline and reproducible.

Formulas (incidence data, T = 20 quadrats)

Chao2 = Sobs + (T−1)/T · Q₁(Q₁−1) / (2(Q₂+1))
Coverage = 1 − Q₁/U · [(T−1)Q₁ / ((T−1)Q₁ + 2Q₂)]
S(t) = Σᵢ [1 − C(T−Yᵢ, t) / C(T, t)]

Q₁, Q₂: taxa in exactly one / two quadrats; U: total incidences. Chao2 with the log-normal 95% interval (Chao 1987).

Why coverage first (V-10)

Chao2 intervals are wide at T = 20. Plot 10: 21 taxa, 11 in a single quadrat and only 1 in two, so Chao2 = 47 (27–129). Coverage carries no interval here: a naive bootstrap over quadrats is biased upwards; a valid one needs iNEXT's assemblage bootstrap. The iNEXT cross-check has not been run yet.

Limitations

  • Estimates, not truth: misidentifications and missing records (C04) are not in the model.
  • Sample coverage is not quality, and not the percentage of species found.
  • Quadrats are paired along one transect, not independent: the intervals are optimistic.

Repeatability

Two plots surveyed twice on the same day share 62–76% of species; quadrat-level agreement ~50%. Only two pairs, different effort (25 vs 53–68 min), so it indicates the size of the noise without measuring it. Suggested: 10% of plots re-surveyed per round by a second recorder.

Summary of the approach

1

Automate only with sufficient evidence

Thresholds are set only where the validation data support them. Effort metrics are reported with their status.

Keep the source data unchanged

Human verdicts and source values are kept. Each label and each flag records its source row and its reason.

Report verification status
